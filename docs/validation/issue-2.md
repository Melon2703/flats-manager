## Spec

Independent review identified two P2 findings:

1. Internal browser history could discard an unfinished receipt without confirmation. Fixed by document navigation for month changes, the native unsaved-entry guard for Back/Forward, and explicit discard before sign-out. A `pageshow` handler resets navigation state and refreshes persisted BFCache restores. Browser regression checks cover canceling Back, accepting navigation after discard, restoring both months, and canceling/confirming sign-out.
2. UTC-based initial month selection could disagree with the owner's local receipt date at a month boundary. Fixed by resolving the browser-local current month before loading obligations and canonicalizing its URL. The regression checks a Tbilisi month boundary and the matching default receipt date.

Both findings were confirmed resolved in the source recheck. The related browser regression cases pass. No scope creep was found. Apartment setup additionally uses immutable retry payloads when its save response is uncertain, preventing changed-payload retries or duplicate creation.

Final review totals: **Standards: 0 findings. Spec: 2 findings, both resolved; 0 unresolved.**

## Practical limits

- The implementation supports regular due days 1–28. Behavior for days 29–31 in short months is awaiting a product decision; no rollover rule is assumed.
- Hosted Supabase configuration, the owner's account, public-signup restrictions, deployment, and backup/restore verification remain setup work. See [README.md](../../README.md).
- There is no claim of independent owner validation, screen-reader certification, complete handling of every rental arrangement, or readiness for real personal/financial data. Expenses, allocation, advances, corrections, and monthly exceptions remain outside this slice.
